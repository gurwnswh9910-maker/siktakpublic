# 우연한 식탁 — 소셜다이닝 자동 운영 MVP

4~6명 저녁 모임의 **신청 → 모의 결제 → 자동 매칭 → 가상 식당 배정 → 단체방·안내 → 대화 주제 → 체크인 → 후기 → 다음 매칭 반영**을 운영자 승인 없이 처리합니다. 운영자는 예외만 확인합니다.

- **데모:** https://siktak-public.onrender.com (로그인 `/login`, 참가자 `/app`, 운영자 `/admin`)
- **테스트 계정:** 참가자 `hello@siktak.demo` · 운영자 `admin@siktak.demo` · 비밀번호는 제출 양식 참고
- **PRD 기능별 확인 방법:** [PRD-VERIFICATION.md](PRD-VERIFICATION.md)
- **직접 배포·로컬 실행:** [DEPLOY.md](DEPLOY.md)

무료 서버라 오래 쉬었다면 첫 접속에 최대 1분 정도 걸릴 수 있습니다.

## 5분 확인 순서

1. 운영자로 로그인 → `회차·식당` → **심사용 시연 회차 만들기** (3일 뒤 회차 + 모의 결제를 마친 합성 참가자 11명)
2. 다른 브라우저에서 참가자로 로그인 → 해당 회차 신청 → 이용권 선택 → 모의 결제
3. 운영자: 회차의 **매칭 시각** → 몇 초 뒤 자동 매칭·확정, 가상 식당 배정, 단체방 생성
4. 참가자: `나의 모임`에서 식당·시간·함께할 사람·**매칭 이유**, 단체방 공지 확인
5. 운영자: **시작 시각** → 단체방에 대화 주제 3개 자동 게시 → 참가자 `체크인하기`
6. 운영자: **종료 시각** → 참가자 후기 요청 → 만족도·재참여·사람별 선호/비선호 입력
7. 시연 회차를 한 번 더 만들고 다시 매칭 → 비선호한 사람과는 같은 테이블이 되지 않음

## 구현 요약

| 영역 | 내용 |
| --- | --- |
| 자동 매칭 | 날짜·지역·4~6명·나이 차 8살 이내·차단/신고/비선호 제외를 필수 조건으로, 성비 → MBTI → 관심사 → 희망 성향 점수(고정 가중치 25:13:7:3, 최소 20점)를 최적화. 정수계획 solver(HiGHS)로 최적해를 증명한 결과만 확정하고, 실패하면 대안 일정·이용권 보관·모의 환불로 자동 연결 |
| 모임 안내 | 테이블별 가상 식당 배정, 단체방 자동 생성, 확정·큐레이션·취소 정책 공지, 하루 전 리마인드, 시작 시각 대화 주제, 발송 재시도·실패 예외 |
| 피드백 | 체크인, 분위기·대화·식당 평가, 재참여·추천 의향, 사람별 선호/비선호(비공개), 신고·차단 → 다음 매칭의 제외 조건과 새 만남 우선에 반영 |
| 운영자 | 예외 중심 대시보드, 예외·작업 큐, 테이블 긴급 수정(미리보기·사유·감사 기록), 대기자 순차 전환, 콘텐츠 관리, 안전 관리, CSV 내보내기 |
| 참가자 | 모바일 웹앱(PWA), 신청·결제·매칭 상태와 다음 안내 시각, 참가 이력·이용권 잔여·다음 일정 추천 |

## 구조

```
브라우저 (참가자 PWA / 운영자 웹)
        │  /api/command, /api/view
        ▼
Next.js 서버 ── PostgreSQL (Prisma) ── 작업 큐(Job 테이블)
                                            ▲
                        worker: 매칭·안내·리마인드·후기 요청·재시도
```

- Next.js 16 · React 19 · TypeScript · Prisma 6 · PostgreSQL 17 · better-auth · HiGHS(WASM) · Web Push
- 예약 작업은 DB 큐에 저장하고 worker가 처리합니다. 무료 배포에서는 웹과 worker가 한 컨테이너에서 함께 돕니다.

## 테스트

`npm test`(단위·DB), `npm run test:e2e`(Playwright 브라우저), GitHub Actions `App checks`가 push마다 타입 검사·테스트·빌드를 실행합니다.

## 범위와 한계

모의 결제·환불과 가상 식당은 해커톤 안내에서 허용한 시연 방식입니다. 실 PG(PAY-04), 실제 식당 예약, 실기기 푸시 수신, 소셜·휴대전화 인증, 학습형 추천(MAT-16)은 구현하거나 검증하지 않았습니다. 주최 측 PRD·제공 데이터는 이 공개 저장소에 포함하지 않습니다.
